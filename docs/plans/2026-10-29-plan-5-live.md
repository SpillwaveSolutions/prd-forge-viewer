# Plan 5: live updates from the authoring tools

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task by task.

**Goal:** When the authoring tools save a document, the author sees the new text, status, and score within 2 seconds, with no action, and sees which documents changed.

**Architecture:** Rust adds `watch.rs`: one file watcher for the open set, using the `notify` crate's events with a 200 ms debounce for each file, and its polling watcher when events are not available (ADR-005). A change to a top-level `.md` file of the set emits the event `set-changed` with the file names. The UI reloads the set with a new `reload_set` command, which does not change the settings, and re-reads the open section. It marks each changed document in the list and shows a change notice on its page (WF-002).

**Tech stack:** Plans 1 to 4, plus `notify` and `notify-debouncer-mini`.

**Spec:** FR-009 (three criteria), NFR-002, WF-002 (the change notice), story US-013, and ADR-005.

## Global constraints

- All earlier constraints stay. The watcher only reads. It never writes to the set folder (OUT-001).
- Only top-level `.md` files of the set count as changes. Files in `grades/` and `diagrams/` and temporary files do not.
- A new set replaces the watcher of the old set, so that events from the old set never reach the window.
- The author sees a change within 2 seconds, p95 (NFR-002).

## Review focus

1. **A burst of saves.** Five saves of one file in 100 ms give one reload, not five. Test in task 1.
2. **A save by rename.** An editor that writes a temporary file and renames it over the document still gives one change for the document. Test in task 1.
3. **A document deleted while the viewer is open.** The set reloads, and the document shows as unreadable, with no crash. Test in task 3.
4. **Another set.** After a second set opens, a change in the first set does not reach the window. Test in task 1.
5. **The open item.** After a reload, the selected item stays selected when it still exists. Test in task 3.

## Tasks

- [ ] (P0) Task 1: watch the set folder
  `SetWatcher::start(folder, on_change)` calls `on_change` with the changed top-level `.md` file names, at most once for each 200 ms window. It falls back to polling when the event watcher cannot start. Tests: one change within 2 s, a burst gives one call, a rename over the file counts, a file in `grades/` does not, and a replaced watcher stops.
- [ ] (P0) Task 2: the watch and reload commands
  `watch_set(folder)` starts the watcher and emits `set-changed`. `reload_set(folder)` loads the set without changing the settings. Test: `reload_set` writes no settings file.
- [ ] (P0) Task 3: show changes in the window
  On `set-changed`, the window reloads the set and the open section, keeps the selected item, marks each changed document, and shows a change notice on a changed page (FR-009, WF-002). Tests in `bun test` for the change state and the notice.
- [ ] (P0) Task 4: MCP checks for phase 3
  `e2e/checks/phase-3-live.mjs` changes a copy of the set while the window shows it, and checks all three FR-009 criteria and NFR-002.
